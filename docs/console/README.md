# موضوع: کنسول واحد (SpiderVIP Console)

داشبورد واحد برای کارهای عملیاتی رسیور.

## کد

- `spidervip/console/` — پوسته + پروکسی + اتصال مشترک (فاز ۲)
- اجرا: `python -m spidervip.cli console` → `http://127.0.0.1:8787/`

## فضاهای کاری

| مسیر UI | موضوع |
|---|---|
| `/` | پوسته + پنل اتصال مشترک |
| `/frequencies/` | به‌روزرسانی فرکانس (همهٔ ماهواره‌ها) |
| `/channels/` | کانال و Favorite |

API اتصال: `GET/POST /api/connection` ، `POST /api/connection/probe` ، `GET /api/version`

## رفتارهای مهم

- **حالت شبیه‌ساز کانال** همراه IP و رمز در `.spidervip_console/connection.json` ذخیره می‌شود و به صفحهٔ کانال‌ها هم می‌رسد. صفحهٔ کانال‌ها دیگر با هر بار باز شدن به رسیور واقعی سوییچ نمی‌کند. فایل قدیمی بدون این فیلد، حالت واقعی (live) در نظر گرفته می‌شود.
- **مسیر فایل‌ها** به ریشهٔ toolkit بسته است، نه پوشهٔ جاری: `.spidervip_console/` و `.spidervip_channels/`.
- **امنیت:** رمز رسیور داخل هر صفحه هست و کنسول خودش ورود ندارد. برای همین bind غیر از `127.0.0.1` فقط با `--allow-remote` قبول می‌شود.
- **تست ارتباط:** پورت‌های 23، 21 و 80 هم‌زمان تست می‌شوند؛ اگر رسیور خاموش باشد حداکثر حدود ۲ ثانیه طول می‌کشد.
- **timeout پروکسی:** Apply کانال ۶۰۰ ثانیه، ارسال فرکانس ۱۲۰ ثانیه، بقیهٔ POSTها ۹۰ و GETها ۶۰ ثانیه. اگر کنسول منتظر نماند، پاسخ JSON با کد 504 و `timed_out` برمی‌گردد. عملیات ممکن است هنوز روی بک‌اند در حال اجرا باشد: کنسول را نبندید و دوباره ارسال نکنید؛ صبر کنید و صفحه را رفرش کنید. نتیجهٔ آخرین Apply در صفحهٔ کانال‌ها دیده می‌شود.
- **ذخیرهٔ اتصال** همیشه JSON برمی‌گرداند. اگر بک‌اند کانال‌ها تنظیمات را نگیرد، `saved: true` و `ok: false` با متن خطا برمی‌گردد.
