# پچ‌کردن فریمور SpiderVIP (یک‌کلیکی)

هدف این پروژه: وقتی شرکت فریمور رسمی جدیدی می‌دهد، بعد از نصب آن روی رسیور، با یک
دستور، بهبودهای اختصاصی خودمان را دوباره روی همان فریمور اعمال کنیم.

اولین بهبودی که همیشه اعمال می‌شود: در منوی تنظیمات/About، جلوی شماره‌ی نسخه عبارت
`patch` نمایش داده شود (مثلاً `1.00.93` تبدیل شود به `1.00.93 patch`) تا مشخص باشد
این فریمور کاستوم است.

## فرمت فایل `.mupg`

- پسوند `.mupg` قالبِ بسته‌ی به‌روزرسانیِ سیستم‌عاملِ **DefineOS** (مبتنی بر لینوکس/Enigma2)
  است که روی رسیورهای این خانواده (از جمله SpiderVIP) استفاده می‌شود. این با «لینوکس بودنِ
  سیستم‌عامل» و باز بودن پورت‌های telnet/ssh/http روی دستگاه هم‌خوانی دارد.
- نسخه‌ای که در منو نمایش داده می‌شود، از یک فایل متنی داخل رroot filesystem خوانده می‌شود
  (فایلی از نوع `image-version`/`imageversion`). پس «مارکِ patch» یعنی همان فایل را هنگام
  پچ ویرایش کنیم و دوباره بسته‌بندی کنیم.

## چرا هنوز به یک نمونه‌ی واقعی `.mupg` نیاز داریم

`.mupg` یک قالبِ باینریِ اختصاصی است (هدر، جدول بخش‌ها، چک‌سام/امضا). اگر بسته را اشتباه
repack کنیم، ممکن است رسیور **بریک (خراب)** شود. به همین دلیل ابزار تا وقتی چیدمان دقیقِ
قالب از روی یک نمونه‌ی واقعی بازمهندسی نشده و یک **round-trip بایت‌به‌بایت** تأیید نشده،
از repackِ فایل `.mupg` واقعی خودداری می‌کند. من به مسیر `F:\Satelite\Spider VIP` روی سیستم
شما دسترسی ندارم، پس لطفاً یک نمونه در اختیار بگذارید.

### چه چیزی بفرستید
یک نمونه‌ی رسمی (مثلاً `SPIDER-VIP_v1.00.92_20260507.mupg`) کافی است. یا خروجی این دستورها را:

```bash
mupg-patch inspect SPIDER-VIP_v1.00.92_20260507.mupg
file        SPIDER-VIP_v1.00.92_20260507.mupg
binwalk -Me SPIDER-VIP_v1.00.92_20260507.mupg
```

با این اطلاعات، هندلرِ unpack/repack را کامل می‌کنم، با round-trip اعتبارسنجی می‌کنم و بعد
`mupg-patch patch` روی خودِ `.mupg` هم کار خواهد کرد.

## استفاده

```bash
pip install -e ".[dev]"

# تحلیل ایمیج (برای بازمهندسی قالب واقعی .mupg)
mupg-patch inspect <firmware.mupg>

# پچِ یک‌کلیکی (اکنون روی یک rootfsِ باز؛ روی .mupg بعد از تأیید هندلر)
mupg-patch patch --in <image-or-rootfs-dir> --out <patched-image>

# مارکِ نسخه مستقیم روی یک rootfsِ باز
mupg-patch mark-version --rootfs <rootfs-dir> --marker patch
```

## نکات
- عملیاتِ مارکِ نسخه ایدمپوتنت است؛ اجرای دوباره هرگز `1.00.93 patch patch` نمی‌سازد.
- بهبودهای بعدی (مثل اصلاحاتِ فریز تصویر/صدا که قبلاً تحلیل شد) به‌صورت پچِ فایل‌محور به
  `mupgpatch/patcher.py` (لیستِ `IMPROVEMENTS`) اضافه می‌شوند تا در همان مرحله‌ی پچ روی
  فریمور جدید هم اعمال شوند.
