# رفع مشکل فریز/نبود تصویر و صدا در رسیور SpiderVIP

این سند برای عیب‌یابی و رفع مشکلِ «نبودِ تصویر و صدا» (فریز تصویر و صدا) در رسیورهای
ماهواره‌ای خانواده‌ی SpiderVIP نوشته شده است؛ در شرایطی که بقیه‌ی بخش‌های دستگاه سالم
کار می‌کنند.

## علائم (شرایط مسئله)

- کنترل ماهواره (سوییچ LNB / DiSEqC / موتور) کار می‌کند.
- تغییر کانال‌ها کار می‌کند.
- خاموش/روشن شدن با ریموت کار می‌کند.
- ورود به منوی تنظیمات کار می‌کند.
- **همه‌ی کانال‌ها تصویر ندارند.**
- **همه‌ی کانال‌ها صدا ندارند.**

## استدلال فنی (چرا مشکل اینجاست؟)

چون **منوی تنظیمات به‌درستی نمایش داده می‌شود**، یعنی پردازنده (SoC)، لایه‌ی گرافیکی رابط
کاربری (OSD) و خروجی تصویر (HDMI/AV) سالم‌اند. در معماری رسیور، منو روی یک «لایه‌ی
گرافیکی» جدا از «لایه‌ی ویدیو» ترکیب می‌شود. پس وقتی منو دیده می‌شود ولی تصویر کانال نه،
یعنی مشکل در مسیرِ **بین تیونر تا دیکودرهای صوت/تصویر** یا در خودِ مرحله‌ی
**دیکود/خروجی صوت‌وتصویر** است — نه در نمایشگر یا پردازنده.

نبودِ هم‌زمانِ صدا و تصویر روی **همه‌ی کانال‌ها** (در حالی که زپینگ کار می‌کند) به یک
اشکالِ مشترکِ بالادستی اشاره دارد؛ نه به یک کانال یا کدک خاص.

## فهرست عوامل و اولویت‌بندی

اولویت بر اساس «احتمال با توجه به علائم» + «ارزان بودن رفع از راه دور» + «شواهد زندهٔ
این پروژه» تعیین شده است. ابتدا ردیف‌های P1→P6 (همان ترتیب ابزار `spidervip`) را
بررسی کنید؛ سپس در صورت نیاز ردیف‌های P7+ را.

### جدول اولویت‌دار کامل

| اولویت | عامل | چرا محتمل است / شاهد پروژه | راه‌حل | از راه دور؟ |
| --- | --- | --- | --- | --- |
| **P1** | مسیر پخش A/V متوقف یا سرویس دیکودر بالا نیست | رایج‌ترین علت؛ منو جدا می‌ماند. شاهد زنده ۲۰۲۶-۰۸-۰۷: `avplay=STOP`، Vid/Aud Disable، بدون `vdec00` | ری‌استارت نرم پخش‌کننده / `bianbiang` (`restart-av-service`) | بله |
| **P2** | Demux PID صوت/تصویر را به دیکودر نمی‌رساند | زپینگ کار می‌کند ولی TS به VDEC/ADEC نمی‌رسد؛ demux گیر یا PID map کهنه | ریست demux + reload PID (`reinit-demux`) | بله |
| **P3** | لایهٔ ویدیو خاموش / Mute میکسر صدا | OSD (GFX) دیده می‌شود؛ لایهٔ VIDEO سیاه یا Send صدا صفر است | `enable-video-plane`، `unmute-audio` | بله |
| **P4** | فرمت خروجی صدا/تصویر با TV ناسازگار | bitstream ردشده یا مود ویدیو خارج از توان TV؛ OSD روی مود امن می‌ماند | صدا `auto`، تصویر `1080p50` | بله |
| **P5** | افت سیگنال / قطع قفل frontend | UI سالم؛ LOCKED ضعیف یا صفر | LNB، کابل، دیش | خیر (دستی) |
| **P6** | کانال FTA به‌اشتباه scrambled | جدول CAS/کلید خراب → دیسکرمبلر A/V را بلاک می‌کند | ریست CAS/تنظیمات روی دستگاه | خیر (دستی) |
| **P7** | نبود respawn برای `bianbiang` | ISSUE-001: `inittab once` + نبود حلقه → هر crash = سیاه دائمی تا قطع برق | پچ `bianbiang.sh` با حلقهٔ نظارت (نسخهٔ ۱.۰۰.۹۳) | بله (استقرار پچ) |
| **P8** | مرگ سرویس‌های کمکی بدون restart | ISSUE-002: `streamrelay` / `satipclient` / `app_console` | supervision سبک در `bianbiang.sh` | بله (استقرار پچ) |
| **P9** | OOM / فشار حافظه در uptime طولانی | ISSUE-003: min_free پایین، dirty بالا؛ مسیر به OOM-kill اپ | sysctl محافظه‌کارتر + zram در صورت نیاز | بله (استقرار پچ) |
| **P10** | طوفان وقفهٔ USB gadget / مسیر `u_service`+`dwc_otg` | freeze ۲۰۲۶-۰۷-۱۱ و forensic ۲۰۲۶-۰۸-۰۷: load≈۱۴، CPU بیکار. روی این فریمور منوی PC-Link/استریم TS **وجود ندارد**؛ USB منو فقط ضبط/بکاپ/آپدیت میزبان است | forensic بگیر؛ `rmmod g_service` ممنوع؛ کاهش ساختاری فقط با کار مهندسی gadget (نه تیک منو) | خیر (منو ندارد) |
| **P11** | بن‌بست زنجیرهٔ HiSilicon (VDEC/VPSS/win/sync) | شمارنده‌ها جلو نمی‌روند؛ `sync=STOP`؛ نودهای `vdec`/`win` غایب | ری‌استارت A/V؛ در حالت شدید reboot نرم | بله |
| **P12** | خطای حمل TS در demux (TEI/CC) یا frontend بدون lock | demux فعال ولی جریان خراب/خالی | سیگنال فیزیکی + در صورت نیاز ریست demux | ترکیبی |
| **P13** | پایگاه کانال خراب (`live_prog` / PID اشتباه) | بعد از اسکن ناقص یا ناهماهنگی با `satellites.xml` | اصلاح/بازسازی دیتابیس؛ commit از WebIF | دستی |
| **P14** | پچ یا فریمور معیوب روی مسیر A/V | UI می‌ماند، دیکود می‌شکند | برگشت پچ / بازیابی از backup | دستی |

ابزار `spidervip` فعلاً P1–P6 را به‌صورت خودکار تشخیص/اعمال می‌کند. P7–P11 از
ممیزی پایداری و forensic زندهٔ همین مخزن آمده‌اند.

### وضعیت مشاهده‌شده روی باکس آزمایش (۲۰۲۶-۰۸-۰۷)

| بخش | وضعیت |
| --- | --- |
| `bianbiang` | در حال اجرا |
| HDMI / OSD | وصل و فعال |
| `avplay00` | **STOP** — ویدیو و صدا Disable |
| دیکودر ویدیو | نود `vdec00` ساخته نشده |
| صدا | Mute off ولی `SendCnt=0` |
| نزدیک‌ترین برچسب | **P1** (مسیر پخش متوقف)؛ در صورت بار USB همزمان **P10** را هم چک کنید |

## پیشنهاد رفع برای مشکل فعلی (باکس آزمایش)

ترتیب پیشنهادی — از کم‌ریسک به پرریسک؛ **بدون فلش کامل**:

1. **تأیید علائم روی TV:** روی یک کانال ماهواره‌ای (نه فقط منو) باشید؛ زپینگ را یک‌بار
   امتحان کنید. اگر بعد از زپینگ `avplay` از STOP خارج شد، مشکل لحظه‌ای بوده است.
2. **ری‌استارت نرم پخش (P1):** با Telnet یک بار `bianbiang` را ببندید تا حلقهٔ
   `bianbiang.sh` دوباره بالا بیاورد؛ بعد از ۳۰–۶۰ ثانیه دوباره
   `cat /proc/msp/avplay00` را بخوانید — باید `CurStatus` دیگر STOP نباشد و PID ویدیو
   غیر از `0x1fff` شود.
3. **اگر هنوز STOP بود — demux/PID (P2):** ریست demux و زپینگ دوباره به همان کانال.
4. **لایهٔ ویدیو / unmute (P3)** و در صورت نیاز خروجی امن HDMI (P4).
5. **USB gadget (P10):** روی این تصویر منوی PC-Link نیست؛ اگر `load≈14` و طوفان
   `dwc_otg`/`service gadget` دیدید فقط forensic بگیرید — خاموش‌کردن «USB ضبط/بکاپ/آپدیت»
   در منو این بار را کم نمی‌کند. جزئیات:
   [`FIRMWARE_UPGRADE_PATCH_PLAYBOOK.md`](FIRMWARE_UPGRADE_PATCH_PLAYBOOK.md) بخش P10.
6. **سیگنال و CAS (P5/P6):** فقط اگر بعد از برگشت `avplay` به RUN هنوز تصویر/صدا نبود.
7. **آخرین راه نرم:** reboot از راه دور (`reboot`)؛ فلش `.mupg` لازم نیست مگر پچ
   معیوب شناخته‌شده باشد.

دستورهای آماده برای گام ۲ (از ریشهٔ مخزن، پس از تأیید شما):

```powershell
# محتویات نمونهٔ cmds.txt — فقط پس از تأیید اجرا شود
# killall bianbiang
# sleep 3
# pidof bianbiang
# cat /proc/msp/avplay00 | head -40
```

## قبل از قطع برق — forensic اجباری

قطع برق سخت‌افزار/MMZ را ریست می‌کند و علائم اغلب برطرف می‌شوند، ولی **شواهد runtime
را هم پاک می‌کند**. تا وقتی اسنپ‌شات ماندگار روی `/data` نوشته نشده، برق را قطع نکنید.

### یک‌بار استقرار ناظر

```powershell
python tools/deploy_freeze_watch.py
```

ناظر در `/data/freeze_tools/` نصب می‌شود و از طریق `/home/gx/local/user_script`
(مسیر موجود در `bianbiang.sh`) بعد از بوت دوباره بالا می‌آید. وقتی امضای فریز
(~۶۰ثانیه `avplay=STOP` با `bianbiang` زنده) پایدار بماند، خودکار به
`/data/freeze_snap/<timestamp>/` می‌نویسد.

### وقتی همین الان فریز می‌بینید

```powershell
python tools/freeze_capture.py
```

تا پیام `DUMP_OK` و فایل `SUMMARY.txt` را ببینید. **بعد از آن** قطع برق مجاز است.

### بعد از روشن‌شدن دوباره

```powershell
python tools/freeze_pull.py          # آخرین اسنپ‌شات → build/freeze_snap/
python tools/freeze_pull.py --list   # فهرست روی باکس
```

محتوای هر اسنپ‌شات: `avplay`/`sync`/`irq`/`ps`/`dmesg`/`db_stat`/`SUMMARY.txt` و برچسب‌هایی
مثل `AV_STOP`, `NO_VDEC`, `USB_IRQ_STORM_SUSPECT`, `DB_DISK_OK`.

برای پورت کل راه‌حل به فریمور ارتقایافته و محدودیت‌های P10 (چرا از Telnet نمی‌شود
PC-Link را خاموش کرد / ممنوعیت `rmmod g_service`):

- [`FIRMWARE_UPGRADE_PATCH_PLAYBOOK.md`](FIRMWARE_UPGRADE_PATCH_PLAYBOOK.md)

## رفع از طریق اتصال آنلاین به رسیور

### دسترسی زنده روی Spider VIP آزمایشگاهی

روی باکس آزمایش این مخزن (`clap4k`) مسیر اصلی **Telnet پورت 23** است؛ SSH معمولاً
فعال نیست. راهنمای کامل IP، login و ابزارها:

- [`NETWORK_ACCESS_GUIDE.md`](NETWORK_ACCESS_GUIDE.md)

نمونهٔ سریع:

```powershell
ping -n 2 192.168.100.102
Test-NetConnection 192.168.100.102 -Port 23
python tools/telnet_run.py cmds.txt
```

ورود: `root` / `root` روی `192.168.100.102` (در صورت تغییر DHCP، IP را از منوی شبکه بگیرید).

### ابزار `spidervip` (بک‌اند SSH)

ابزار `spidervip` وضعیت مسیر صوت/تصویر را می‌خواند، عوامل را به‌ترتیب اولویت رفع
می‌کند و بعد از هر اقدام دوباره تصویر/صدا را بررسی می‌کند. بک‌اند آنلاین آن روی
**SSH + paramiko** است؛ اگر روی باکس شما فقط Telnet باشد، فعلاً از
`tools/telnet_*.py` استفاده کنید یا با `--simulate` بدون سخت‌افزار تست کنید.

### پیش‌نیاز (وقتی SSH روی باکس فعال است)

- رسیور و رایانه روی یک شبکه باشند و آدرس IP رسیور مشخص باشد.
- برای بک‌اندِ آنلاین SSH: `pip install paramiko`.

### دستورها

```bash
# عیب‌یابی: فهرست عوامل محتمل به‌ترتیب اولویت
spidervip diagnose --host 192.168.1.50 --user root --password ****** --profile enigma2

# رفع: اعمال پچ‌های اولویت‌بندی‌شده و بررسی مجدد
spidervip repair --host 192.168.1.50 --user root --password ****** --profile enigma2

# فقط برنامه‌ریزی بدون تغییر روی دستگاه
spidervip repair --host 192.168.1.50 --dry-run
```

اگر مدل باکس شما با پروفایل `enigma2` سازگار نیست، پروفایل `linux-stb` را امتحان کنید یا
دستورهای پوسته را در `spidervip/ssh_receiver.py` برای دستگاه خود تنظیم کنید.

### شبیه‌ساز (برای آموزش و تست بدون سخت‌افزار)

بدون نیاز به رسیور واقعی می‌توانید همان جریان را روی شبیه‌ساز اجرا کنید:

```bash
spidervip faults                                  # فهرست خطاهای قابل‌تزریق
spidervip diagnose --simulate --fault player-crash
spidervip repair   --simulate --fault demux-stuck --fault audio-muted
```

## روش رفع پیشنهادی (خلاصه‌ی گام‌به‌گام)

1. جدول اولویت را از P1 به پایین طی کنید؛ روی باکس Telnet ابتدا وضعیت
   `/proc/msp/avplay00` را بخوانید.
2. در صورت امکان `spidervip diagnose` / `repair` را اجرا کنید (نیازمند SSH)؛ وگرنه
   همان ترتیب را با `tools/telnet_run.py` اعمال کنید.
3. اگر خروجی «picture OK, sound OK» شد (یا `avplay` در RUN با PID معتبر)، مشکل حل شده است.
4. موارد P5/P6/P12–P14 نیازمند اقدام دستی/فیزیکی‌اند؛ طبق جدول بالا پیش بروید.

## ثبت برای استفاده‌های بعدی

- خروجیِ `diagnose`/`repair` را (به‌ویژه با `--json`) برای هر دستگاه ذخیره کنید تا سابقه‌ی
  عیب‌یابی بماند.
- اگر برای مدل جدیدی دستورهای پوسته را در پروفایل تنظیم کردید، آن پروفایل را در
  `spidervip/ssh_receiver.py` اضافه کنید تا برای دفعات بعد آماده باشد.
