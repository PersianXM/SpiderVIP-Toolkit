# مدیریت فرکانس (Frequency Manager)

> **محل در مخزن مرکزی:** `spidervip/frequency/`  
> بخشی از موضوعات SpiderVIP ([`docs/TOPICS.md`](../../docs/TOPICS.md))؛ در آینده زیر
> **SpiderVIP Console** در کنار کانال/Favorite قرار می‌گیرد.  
> اجرا از همین پوشه: `run.bat` یا `python app.py` → <http://127.0.0.1:5000>

وب‌اپ Flask برای **مدیریت لیست فرکانس / TP** روی رسیور Spider VIP: واکشی از منبع
خارجی (در حال حاضر صفحات **LyngSat**)، مقایسهٔ نظیر‌به‌نظیر با فرکانس‌های ماهوارهٔ
انتخاب‌شده در پایگاه رسیور، افزودن/حذف انتخابی، و انتقال امن به دستگاه زنده.

LyngSat نام محصول نیست؛ فقط منبع دادهٔ پیش‌فرض برای scrape است.

## گردش‌کار (Workflow)

0. (اختیاری) کاربر IP/کاربر/رمز رسیور را وارد و **«واکشی زنده از رسیور»** را می‌زند؛
   آنگاه فهرست ماهواره‌ها و فرکانس‌ها مستقیماً از خود دستگاه (فایل زنده
   `default_data.xml`) خوانده می‌شود. اگر این کار انجام نشود، از نسخه‌ی داخلی فریمور
   استفاده می‌شود.
1. کاربر از فهرست ماهواره‌های موجود در رسیور یکی را انتخاب می‌کند. **فرکانس‌های
   همان ماهواره از رسیور خوانده می‌شود** تا در مقایسه استفاده شود.
2. کاربر لینک صفحه‌ی LyngSat را وارد می‌کند.
3. برنامه فرکانس‌ها را از لینک واکشی می‌کند.
4. خروجی در یک **جدول مقایسه‌ای** نمایش داده می‌شود: کدام فرکانس‌ها مشترک‌اند و
   کدام فقط در یک طرف وجود دارند.
5. کاربر در جدول برای هر فرکانس یکی از دو کار را انتخاب می‌کند:
   - ستون **«افزودن»** (سبز): فرکانس‌های منبع (LyngSat) که می‌خواهد به رسیور اضافه شوند.
   - ستون **«حذف»** (قرمز): فرکانس‌های موجود در رسیور که می‌خواهد حذف شوند.
6. با «اعمال تغییرات»، فرکانس‌های انتخاب‌شده برای افزودن **اضافه** و فرکانس‌های
   انتخاب‌شده برای حذف **حذف** می‌شوند (هر دو با حفظ ساختار XML).
7. فرکانس‌های افزوده‌شده در **همان زیرمجموعه‌ی ماهواره‌ی انتخاب‌شده** و به‌عنوان
   فرکانس‌های N+1، N+2، … قرار می‌گیرند. فایل نهایی `default_data.xml` هم قابل
   دانلود است و هم می‌تواند **به‌صورت خودکار روی رسیور نصب** شود.

## واکشی زنده و افزودن/حذف

- **واکشی زنده:** با انتخاب ماهواره، فرکانس‌های همان ماهواره از پایگاه‌داده‌ی فعال
  خوانده می‌شوند. اگر «واکشی زنده از رسیور» را زده باشید، این داده‌ها از خود دستگاه
  (از طریق FTP، فایل `default_data.xml`) می‌آید؛ در غیر این‌صورت از نسخه‌ی داخلی.
- **افزودن:** فرکانس‌های منبع به انتهای ماهواره افزوده می‌شوند.
- **حذف:** هر فرکانسِ موجود در رسیور که ستون «حذف» آن تیک بخورد، از ماهواره حذف
  می‌شود. افزودن و حذف می‌توانند هم‌زمان در یک مرحله اعمال شوند.


## انتقال خودکار به رسیور

رسیور یک دستگاه Enigma2 است که هنگام روشن‌شدن FTP (پورت ۲۱) و Telnet (پورت ۲۳)
را فعال می‌کند (login: `root`/`root`). ماژول `deploy.py` انتقال را کاملاً خودکار
انجام می‌دهد:

1. اتصال FTP به رسیور (IP/کاربر/رمز از فرم رابط کاربری).
2. **پشتیبان‌گیری** از فایل فعلی روی دستگاه →
   `/usr/local/default/default_data.bak`.
3. جایگزینی `/usr/local/default/default_data.xml` با نسخه‌ی ساخته‌شده.
4. اتصال Telnet و تلاش برای reload تنظیمات؛ اگر تصویر رسیور رِلود خودکار نداشت،
   کافی است از منوی رسیور «Reload Settings» بزنید یا یک‌بار دستگاه را ری‌استارت کنید.

در رابط کاربری، پس از مرحله‌ی ۶، کارت «۷) خروجی نهایی و انتقال به رسیور» ظاهر می‌شود؛
IP رسیور (پیش‌فرض `192.168.100.102`)، کاربر و رمز را وارد کرده و دکمه‌ی
«انتقال خودکار به رسیور» را بزنید. گزارش مرحله‌به‌مرحله (اتصال، پشتیبان، آپلود،
رِلود) نمایش داده می‌شود. اگر رسیور در دسترس نبود، پیام خطا همراه با راهنمایی نشان
داده می‌شود و می‌توانید به‌جای آن، فایل را دانلود و دستی با FTP جایگزین کنید.

## مهم: کدام فایل واقعاً «TP List» رسیور را می‌سازد؟ (ریشه‌ی مشکلِ حذف)

قبلاً ابزار روی فایلِ **«پیش‌فرض کارخانه»** کار می‌کرد، ولی رسیور در حال کار از آن
استفاده نمی‌کند. مسیر درست برای pull/deploy زنده در README تاریخی و کد `deploy.py`
مستند شده است؛ همیشه روی پایگاه فعال دستگاه کار کنید، نه روی squashfs کارخانه.

## پایگاه داخلی

`receiver_data.xml` نسخه‌ی همراه فریمور برای کار آفلاین است (۲۲۷ ماهواره). ماژول
`receiver.py` این فایل را می‌خواند، فرکانس‌های منبع را به واحدهای رسیور
(frequency=kHz، symbol_rate=S/s و کدهای polarization/fec/system/modulation) تبدیل
می‌کند و ترانسپوندرهای جدید را به ماهواره‌ی انتخابی می‌افزاید.

## اجرا

روش ساده (ویندوز): روی `run.bat` دوبار کلیک کنید.

یا دستی:

```
cd spidervip\frequency
python -m pip install -r requirements.txt
python app.py
```

سپس مرورگر را باز کنید: <http://127.0.0.1:5000>

## امکانات

- ورود لینک منبع (LyngSat) از طریق فرم وب
- نمایش نتیجه در جدول
- دانلود فایل `frequencies.txt`
- ذخیره‌ی خودکار یک نسخه در پوشه‌ی `output\` با نام زمان‌دار
- **جدول مقایسه‌ای رسیور ↔ منبع:** فرکانس‌های رسیور در کنار فرکانس‌های LyngSat
  به‌صورت نظیر‌به‌نظیر؛ مشترک‌ها روبه‌روی هم و موارد یک‌طرفه جداگانه مشخص می‌شوند.

## قوانین فیلترینگ

1. **فید (Feeds):** اگر مقدار هر یک از ستون‌های SID / Provider Name / Channel Name
   شامل «feed» باشد (چه روی ردیف اصلی فرکانس و چه در هر یک از کانال‌های زیرمجموعه)،
   کل آن فرکانس حذف می‌شود.

> **توجه:** قانون قبلی «حذف فرکانس‌هایی که همه‌ی کانال‌هایشان رمزگذاری‌شده‌اند»
> حذف شده است؛ از این پس ستون Encryption بررسی نمی‌شود و ترانسپوندرهای رمزگذاری‌شده
> نیز در خروجی می‌آیند.

> نکته درباره‌ی ساختار LyngSat: در LyngSat مقادیر فرکانس، SR/FEC و Provider Name
> روی یک ردیف قرار دارند و ترانسپوندرهای فید معمولاً فقط نشانگر «(feeds)» را روی
> همان ردیف دارند و کانال زیرمجموعه ندارند؛ به همین دلیل بررسی فید روی خودِ ردیفِ
> فرکانس نیز انجام می‌شود.

## مقاوم‌سازی شبکه

برای رفع خطای `SSL: UNEXPECTED_EOF_WHILE_READING` که در بعضی شبکه‌ها رخ می‌دهد:

- چند بار تلاش مجدد (retry) با تأخیر
- چرخش User-Agent
- fallback به یک TLS context آسان‌گیر

اگر باز هم خطای SSL دریافت کردید، معمولاً به دلیل فیلترینگ شبکه یا فایروال است؛
از یک شبکه/اینترنت دیگر یا VPN استفاده کنید.

## ساختار فایل‌ها

```
spidervip/frequency/
├── app.py                # سرور Flask (satellites/scrape/export/download)
├── scraper.py            # هسته‌ی واکشی، پارس و مقایسه (منبع: LyngSat)
├── receiver.py           # خواندن پایگاه‌داده‌ی رسیور و افزودن فرکانس‌ها
├── deploy.py             # انتقال خودکار به رسیور (FTP آپلود + Telnet reload)
├── receiver_data.xml     # نسخه‌ی default_data.xml فریمور (۲۲۷ ماهواره)
├── requirements.txt
├── run.bat               # اجرای سریع در ویندوز
├── templates/
│   └── index.html        # رابط کاربری Frequency Manager
└── output/               # فایل‌های خروجی (txt و XML ساخته‌شده؛ در Git نیست)
```
