# به‌روزرسانی فرکانس (Frequency update)

لیست ترانسپوندر (TP) **همهٔ ماهواره‌های** رسیور را با لیست روزانهٔ OpenPLi هم‌گام می‌کند.
OpenPLi این لیست را هر روز از **LyngSat** می‌سازد؛ پس معیار همچنان LyngSat است، بدون scrape کردن HTML.

- رابط: فضای کاری `/frequencies/` در **کنسول SpiderVIP** (`RUN.bat`)
- اجرای مستقل: `python -m spidervip.frequency` → `http://127.0.0.1:5000/`
- مستند موضوع و یافته‌های فنی: [`docs/frequency/README.md`](../../docs/frequency/README.md)

## گردش کار

1. **بررسی تغییرات** — آخرین `satellites.xml` از GitHub دانلود و لیست زندهٔ رسیور خوانده می‌شود (روی رسیور فقط خواندن).
2. **بازبینی** — برای هر ماهواره: اصلاح پارامتر، TP جدید، TP‌ای که در منبع نیست؛ انتخاب تک‌به‌تک یا گروهی.
3. **اعمال** — snapshot کامل روی رسیور، ارسال، ثبت در رسیور، راه‌اندازی دوباره و مقایسهٔ تک‌تک TPها.
4. **برگشت** — هر کدام از سه snapshot آخر با یک کلیک.

## ساختار کد

```
spidervip/frequency/
├── core/              فقط کتابخانهٔ استاندارد، سازگار با Python 3.9 (برای اجرای بعدی روی خود رسیور)
│   ├── satxml.py      خواندن/نوشتن satellites.xml دقیقاً با قالب رسیور
│   ├── source.py      دانلود و اعتبارسنجی منبع OpenPLi
│   ├── pairing.py     جفت کردن ماهواره‌ها با موقعیت مداری + باند (نه نام)
│   ├── lamedb.py      TPهای دارای کانال در lamedb (برای محافظت)
│   ├── diff.py        مقایسهٔ TP به TP (same / changed / new / gone / skipped / protected)
│   └── plan.py        ساخت برنامهٔ قابل بازبینی و اعمال انتخاب‌ها
├── deploy.py          تراکنش روی رسیور: snapshot → ارسال → ثبت → تأیید → برگشت
├── webapp.py          Flask؛ کارهای طولانی به‌صورت job پس‌زمینه
├── templates/index.html, static/freq.{js,css}
└── __main__.py        اجرای مستقل
```

پوشهٔ کاری روی PC: `<toolkit>/.spidervip_frequency/` (لیست رسیور و منبع، `plan.json`، فایل‌های ساخته‌شده در `out/`، گزارش‌ها در `reports/`). در Git نیست.

## API (زیر `/frequencies/` در کنسول)

| مسیر | کار |
|---|---|
| `POST /api/check` `{host,user,password}` | job: دانلود منبع + خواندن رسیور + ساخت برنامه |
| `GET /api/plan` | خلاصهٔ برنامه (بدون ردیف‌ها) + `default_selected` |
| `GET /api/plan/sat/<box_index>` | ردیف‌های یک ماهواره |
| `POST /api/build` `{selected:[ids]}` | ساخت satellites.xml از انتخاب |
| `GET /api/download` | دانلود آخرین فایل ساخته‌شده |
| `POST /api/deploy` `{host,…,selected,reboot_verify}` | job: اعمال روی رسیور |
| `POST /api/snapshots` `{host,…}` | فهرست snapshotهای روی رسیور |
| `POST /api/rollback` `{host,…,snapshot,hard}` | job: برگشت |
| `GET /api/job` | وضعیت job جاری (صفحه هر ۱٫۵ ثانیه می‌پرسد) |

شناسهٔ ردیف‌ها `"<box_index>.<c|n|g|s><k>"` است (`c` اصلاح، `n` جدید، `g` نبودن در منبع، `s` ردشده).

## قواعد

- TPهایی که کانال ذخیره‌شده دارند (`lamedb`) هرگز اصلاح یا حذف نمی‌شوند؛ رسیور آن‌ها را از `lamedb` دوباره می‌سازد
  (`core/lamedb.py`). این ردیف‌ها «دارای کانال» نمایش داده می‌شوند و قابل انتخاب نیستند.
- ثبت در رسیور ردیف‌های تکراری کانال را یکی می‌کند؛ تأیید فقط کاهش کانال‌های یکتا را خطا می‌داند و تفاوت Favoriteها را گزارش می‌کند.
- TPهای منبع قبل از مقایسه به قالب رسیور درمی‌آیند: L→H، R→V، فرکانس به مگاهرتز کامل (رو به پایین).
- نام، ویژگی‌ها و ترتیب ماهواره‌ها هرگز عوض نمی‌شود (تنظیمات Motor/USALS به رکورد ماهواره بسته است).
- TPهای موجود در جای خودشان اصلاح می‌شوند؛ TPهای جدید ته همان ماهواره اضافه می‌شوند.
- «Auto» در منبع (FEC یا مدولاسیون = 0) مقدار مشخص رسیور را پاک نمی‌کند.
- TPهای multistream / T2-MI / PLS غیرپیش‌فرض اضافه نمی‌شوند (رسیور `is_id` را نگه نمی‌دارد)؛ فقط گزارش می‌شوند.
- حذف فقط برای ماهواره‌ای پیش‌انتخاب می‌شود که منبع حداقل ۳ TP برایش دارد و حداکثر ۵۰٪ TPهای رسیور را حذف می‌کند.
- ماهواره‌هایی که در منبع جفت ندارند دست‌نخورده می‌مانند.
- `live_prog` هرگز بایت‌به‌بایت ویرایش نمی‌شود؛ فقط کامل کپی (snapshot) یا کامل برگردانده می‌شود.
